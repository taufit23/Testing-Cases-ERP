# 06. Rekonsiliasi Bank & Pajak Daerah

> Prasyarat: [`05-aset-tetap-hotel-dan-anggaran.id.md`](./05-aset-tetap-hotel-dan-anggaran.id.md) — Bank BCA Operasional (`AST-02`) saldo GL = **271.250.000** (setelah akuisisi aset). Endpoint: **Bank Reconciliations — `{create|complete}`**, **Tax Summary**.

## 1. Rekonsiliasi Bank BCA Operasional

**Field validasi aktual `finance/bank-reconciliations/create`**: `bank_account_id` (required), `period_start`/`period_end` (required, `period_end` `after_or_equal:period_start`), `opening_balance`/`closing_balance`/`statement_balance` (nullable numeric), `notes`. `difference = statement_balance − closing_balance` dihitung server-side, `reconciliation_number` auto-generate format `RCN/{tahun}/{bulan}/{urutan}`.

Kasus realistis: sistem mencatat saldo Bank BCA 271.250.000, tapi mutasi rekening aktual di bank cuma 271.200.000 — selisih Rp 50.000 biaya administrasi bulanan yang **belum** dijurnal.

| Skenario                                                            | Payload kunci                                                                                                                                                                                                             | Hasil                                                                                                                 |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Positif — buat rekonsiliasi awal (masih selisih)                    | `POST finance/bank-reconciliations/create {bank_account_id:<AST-02 bank account>, period_start:"2026-02-01", period_end:"2026-02-10", opening_balance:350000000, closing_balance:271250000, statement_balance:271200000}` | 200 — `reconciliation_number` auto, `difference = 271200000 − 271250000 = -50000`, `status:"draft"`                   |
| Negatif — complete dengan selisih belum nol                         | `POST finance/bank-reconciliations/complete {slug}`                                                                                                                                                                       | Response `warn` — "Reconciliation has unresolved difference of -50000", status TETAP `draft` (tidak jadi `completed`) |
| Positif — jurnal penyesuai biaya admin bank                         | `code:"JRN-009"`, `date:"2026-02-10"`, `lines:[{BBN-04,debit:50000},{AST-02,credit:50000}]` → post                                                                                                                        | 200 — Bank BCA GL = 271.250.000−50.000=**271.200.000** (kini cocok dengan mutasi bank aktual)                         |
| Positif — buat ulang rekonsiliasi dengan closing_balance terkoreksi | `POST .../create {..., closing_balance:271200000, statement_balance:271200000}`                                                                                                                                           | 200 — `difference: 0`                                                                                                 |
| Positif — complete                                                  | `POST .../complete {slug}`                                                                                                                                                                                                | 200 — `status:"completed"`                                                                                            |
| Negatif                                                             | `period_end` sebelum `period_start`                                                                                                                                                                                       | 422 — gagal `after_or_equal:period_start`                                                                             |

## 2. Rekap PPN Masukan/Keluaran — Pembuktian PB1 TIDAK Muncul

`reports/tax-summary` membaca dari tabel `journal_taxes`, yang HANYA terisi untuk baris jurnal pada akun yang diflag `is_tax:true` + `tax_id` terisi (lihat `Journal::createLines()`). PB1 (`LIA-03`) di suite ini SENGAJA dibuat sebagai akun liabilitas manual biasa TANPA `is_tax`/`tax_id` (file `00` §1) — karena PB1 pajak daerah, bukan PPN, dan backend hanya punya satu tabel `taxes` yang dipakai laporan ini murni untuk PPN.

| Skenario                                  | Payload kunci                                                                                                        | Hasil                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif                                   | `POST reports/tax-summary {start_date:"2026-02-01", end_date:"2026-02-06"}`                                          | 200 — `ppn_keluaran` menampilkan `LIA-04` dengan `total_masukan`=... dari §1.4 (220.000) + §1.5 (165.000) = **385.000**; `ppn_masukan` menampilkan `AST-05` dari §1.6 = **880.000**; `net_payable` = 385.000 − 880.000 = **−495.000** (lebih bayar, PPN Masukan > PPN Keluaran di periode ini)                                                                                                                                               |
| **Positif — pembuktian PB1 tidak muncul** | Cek response `tax-summary` di atas untuk baris `LIA-03`                                                              | `LIA-03` **TIDAK ADA** di `ppn_masukan` maupun `ppn_keluaran` — walau `LIA-03` menerima kredit 454.545 di §1.3 (jurnal `JRN-003`), baris itu TIDAK pernah masuk `journal_taxes` karena `LIA-03` tidak diflag `is_tax`. PB1 harus direkap MANUAL oleh operator (mis. lewat `general-ledger/detail-ledger` filter `account_id:<LIA-03>`), bukan lewat laporan pajak otomatis — dokumentasikan sebagai batasan sistem yang disengaja, BUKAN gap |
| Positif — rekap PB1 manual                | `POST accounting/general-ledger/detail-ledger {account_id:<LIA-03>, start_date:"2026-02-01", end_date:"2026-02-06"}` | 200 — 1 baris mutasi kredit 454.545, saldo akhir **8.454.545** (cocok dengan file `01`)                                                                                                                                                                                                                                                                                                                                                      |
