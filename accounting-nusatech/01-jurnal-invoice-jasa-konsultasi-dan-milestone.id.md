# 01. Jurnal Invoice Jasa Konsultasi & Milestone Proyek

> **Ciri Khas Skenario**: Pengakuan pendapatan jasa recurring (managed services, `BU-MANAGED`) vs milestone proyek (software development, `BU-CONSULT`), ditambah transaksi kas harian sisi retail (`BU-RETAIL`) — SEMUANYA di branch **PT NUSATECH** yang sama, dipisah murni via `business_unit_id` di baris jurnal (bukan lewat branch/COA terpisah).
> Format pengujian: **Positif** / **Negatif** / **Netralisasi**. Semua endpoint di **Journals** (`accounting/journals/*`). Prasyarat: master data [`00`](./00-profil-perusahaan-dan-master-data.id.md) sudah ada.

> ⚠️ **Tidak ada fitur recurring invoice otomatis di backend** (`grep -ri recurring app/` nihil kecuali dokumen ini). "Tagihan managed-service bulanan" di judul berarti transaksi retainer dicatat manual berulang tiap bulan lewat `Journals — create`, BUKAN job terjadwal. Jangan uji fitur otomasi yang tidak ada.

> Karena hanya 1 branch, tidak ada switch-context di sepanjang file ini — cukup pastikan active branch tester = PT NUSATECH. `account_id` yang dipakai SELALU dari COA yang sama (dibuat sekali di file 00 §4); yang berubah antar transaksi hanyalah `business_unit_id` per baris jurnal untuk menandai divisi mana yang bertanggung jawab.

## 1.1 Create Jurnal — Tagihan Managed Service Bulanan (BU-MANAGED)

Transaksi: tagih kontrak Managed IT Support bulanan ke PT Sinergi Pangan Nasional Rp 12.000.000 + PPN Keluaran 11% (Rp 1.320.000).

| Skenario                | Payload kunci                                                                                                                                                                                                                                                                                                       | Hasil                                                                                                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif                 | `POST accounting/journals/create {code:"JRN-XXX", date:"2026-08-05", lines:[{account_id:<Piutang Usaha AST-04>, debit:13320000}, {account_id:<Pendapatan Managed Services PDT-02>, credit:12000000, business_unit_id:<BU-MANAGED>, tax_rate:11}, {account_id:<PPN Keluaran LIA-02>, credit:1320000, tax_rate:11}]}` | 200 (macro `successWithData` selalu HTTP 200), journal `status:draft`/`pending-review`, `posted_at` NULL. **Create TIDAK otomatis posting** — GL baru terbentuk setelah `PUT accounting/journals/post` dipanggil terpisah |
| Negatif — tidak balance | Salah ketik credit PPN jadi 1.200.000 (bukan 1.320.000)                                                                                                                                                                                                                                                             | Journal tetap tersimpan tapi jatuh ke status `draft` biasa (bukan pending-review/approval) — cek via `show`, JANGAN asumsikan ditolak dengan error 422                                                                    |
| Negatif — lines < 2     | Kirim 1 baris saja                                                                                                                                                                                                                                                                                                  | 422, `lines` minimal 2 (`min:2`)                                                                                                                                                                                          |
| Lanjutan                | `PUT accounting/journals/post {id}`                                                                                                                                                                                                                                                                                 | `posted_at` terisi, `general_ledgers` baru dibuat — verifikasi lewat file 02                                                                                                                                              |
| Netralisasi             | `DELETE accounting/journals/delete {id}` (selama draft/belum posted), atau `POST accounting/journals/reverse` kalau sudah posted                                                                                                                                                                                    |

## 1.2 Create Jurnal — Milestone Proyek Software Development (BU-CONSULT)

Transaksi: milestone ke-2 proyek custom software untuk PT Solusi Niaga Digital selesai, tagih Rp 45.000.000 + PPN Keluaran 11% (Rp 4.950.000). Klien memotong **PPh 23** 2% dari nilai jasa (Rp 900.000) sebagai kredit pajak kita.

| Skenario    | Payload kunci                                                                                                                                                                                                                                                                                                                    | Hasil                                                                                                                                                                                                                             |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif     | `lines:[{account_id:<Piutang Usaha AST-04>, debit:49050000}, {account_id:<Uang Muka PPh 23 AST-07>, debit:900000}, {account_id:<Pendapatan Jasa Konsultasi PDT-01>, credit:45000000, business_unit_id:<BU-CONSULT>, tax_rate:11}, {account_id:<PPN Keluaran LIA-02>, credit:4950000, tax_rate:11}]}` — 4 baris, Dr=Cr=49.950.000 | 200, journal draft, balance seimbang. Pola ini (piutang bersih setelah potongan PPh 23 + baris terpisah kredit pajak) **BUKAN dihitung otomatis oleh sistem** — semua angka dihitung manual di payload, controller cuma cek Dr=Cr |
| Negatif     | Lupa kurangi Piutang Usaha dengan PPh 23 (debit Piutang tetap 49.950.000, padahal kas yang akan diterima cuma 49.050.000)                                                                                                                                                                                                        | Jurnal tetap lolos (Dr=Cr masih seimbang karena user yang salah asumsi, bukan validasi sistem) — dokumentasikan sebagai kesalahan input manusia, bukan bug backend                                                                |
| Netralisasi | Reverse setelah posted                                                                                                                                                                                                                                                                                                           |

## 1.3 Create Jurnal — Pengakuan Pendapatan Diterima Dimuka (BU-MANAGED)

Transaksi: kontrak retainer tahunan PT Sinergi Pangan Nasional sudah dibayar di muka (tercatat di saldo awal LIA-04 Rp 30.000.000). Bulan ini diakui Rp 5.000.000 sebagai pendapatan managed-service berjalan.

| Skenario                                                       | Payload kunci                                                                                                                                                                                              | Hasil                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif                                                        | `lines:[{account_id:<Pendapatan Diterima Dimuka LIA-04>, debit:5000000, business_unit_id:<BU-MANAGED>}, {account_id:<Pendapatan Managed Services PDT-02>, credit:5000000, business_unit_id:<BU-MANAGED>}]` | 200, journal draft, balance Dr=Cr=5.000.000                                                                                                                                                                                                                                                   |
| Negatif — amortisasi melebihi saldo Pendapatan Diterima Dimuka | Debit LIA-04 sebesar 35.000.000 (saldo cuma 30.000.000)                                                                                                                                                    | **Backend TIDAK memvalidasi saldo akun sebelum posting** — `Journal::create()`/`post()` cuma cek Dr=Cr di level jurnal, tidak cek `chart_of_accounts_balances`. Jurnal akan lolos & posted, akun LIA-04 jadi saldo debit (minus/negatif) — dokumentasikan sebagai gap, bukan "ditolak sistem" |
| Netralisasi                                                    | Reverse setelah posted                                                                                                                                                                                     |

## 1.5 Create Jurnal — Penjualan Tunai Retail (BU-RETAIL, bukan lewat Sales module)

> Skenario ini murni untuk menguji jurnal manual sisi retail SEBELUM alur Sales lengkap (lihat [`../sales-nusatech/`](../sales-nusatech/) untuk SO/Invoice yang lebih realistis). Berguna kalau tester ingin verifikasi tag `business_unit_id:<BU-RETAIL>` independen dari transaksi divisi lain, tanpa perlu isolasi branch (karena memang cuma 1 branch).

Transaksi: jual tunai 1 unit Keyboard Mechanical Logitech G213 ke walk-in customer Rp 650.000 + PPN Keluaran 11% (Rp 71.500), HPP Rp 450.000.

| Skenario    | Payload kunci                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Hasil                                                                                                                                                                                                                                                                            |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif     | `lines:[{account_id:<Bank Mandiri Operasional AST-03>, debit:721500}, {account_id:<Pendapatan Penjualan Barang Elektronik PDT-03>, credit:650000, business_unit_id:<BU-RETAIL>, tax_rate:11}, {account_id:<PPN Keluaran LIA-02>, credit:71500, tax_rate:11}, {account_id:<HPP Barang Elektronik HPP-01>, debit:450000, business_unit_id:<BU-RETAIL>}, {account_id:<Persediaan Barang Dagang Elektronik AST-05>, credit:450000, business_unit_id:<BU-RETAIL>}]` | 200, 5 baris, Dr=Cr=721.500+450.000=1.171.500. **Jurnal manual TIDAK mengurangi `sku_stocks` Inventory** — kalau ingin stok toko konsisten, kurangi stok terpisah lewat Stock Adjustment atau pakai jalur Sales resmi (lihat [`../inventory-nusatech/`](../inventory-nusatech/)) |
| Netralisasi | Reverse setelah posted, dan kembalikan stok manual kalau sempat dikurangi terpisah                                                                                                                                                                                                                                                                                                                                                                             |

## Netralisasi

- Hapus jurnal draft via `DELETE accounting/journals/delete`, atau `POST accounting/journals/reverse` untuk jurnal yang sudah posted (tidak ada "un-post").
- Ingat: reverse jurnal ADDITIVE (posting balik, bukan hapus GL asli) sejak fix [[project_journal_reverse_nets_wrong_bug]] — net efek 0, bukan −2×.
