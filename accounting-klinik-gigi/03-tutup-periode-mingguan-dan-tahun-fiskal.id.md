# 03. Tutup Periode Mingguan & Tahun Fiskal

## 1. Close Accounting Period — Minggu 1

| Skenario                                                       | Detail                                                                                                                                      | Hasil                                                                                                                                                                                                                   |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Negatif — close sebelum minggu berakhir                        | Coba `PUT client-master/accounting-period/close {id:<Minggu 1>}` di tanggal SEBELUM `end_date` periode (2026-01-07) kalau ada guard tanggal | Tergantung implementasi — kalau tidak ada guard tanggal (close boleh kapan saja asal semua transaksi valid), catat sebagai perilaku aktual, bukan bug (banyak sistem akuntansi memang izinkan close periode lebih awal) |
| Positif — close normal                                         | `PUT client-master/accounting-period/close {id:<Minggu 1>}`                                                                                 | 200, `is_closed:true`. Semua jurnal T1-T5 (tanggal 2026-01-02 s/d 2026-01-07) sudah terposting sebelum close ini                                                                                                        |
| **Negatif — posting jurnal baru ke periode yang sudah closed** | Coba `POST accounting/journals/create {date:"2026-01-04", ...}` (tanggal masuk Minggu 1 yang sudah closed)                                  | Ditolak dengan pesan jelas (mis. "accounting_period_is_closed" atau serupa) — BUKAN 500, BUKAN silent-success yang bikin GL periode closed berubah diam-diam                                                            |
| Positif — reopen                                               | `PUT client-master/accounting-period/reopen {id:<Minggu 1>}` (kalau endpoint ini ada)                                                       | 200, `is_closed:false` — dipakai HANYA untuk uji kemampuan reopen, setelah ini WAJIB di-close lagi sebelum lanjut §2 (lihat Netralisasi)                                                                                |
| Netralisasi                                                    | Close ulang Minggu 1 setelah selesai uji reopen                                                                                             | `is_closed:true` lagi, supaya urutan close periode berikutnya konsisten                                                                                                                                                 |

## 2. Close Accounting Period — Minggu 2, 3, 4 (berurutan)

| Skenario                                                     | Detail                                                                                                                                                                                | Hasil                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Negatif — lompat urutan close**                            | Coba close Minggu 3 SEBELUM Minggu 2 di-close (asumsi sistem punya guard "next period only" seperti disebut di suite retail file `09-skenario-lanjutan-dan-edge-case-lapangan.id.md`) | Kalau ada guard: ditolak, harus close berurutan mulai dari periode paling awal yang belum closed. Kalau TIDAK ada guard: berhasil closed di luar urutan — catat sebagai 🆕 gap kontrol kalau ternyata BISA (idealnya periode akuntansi ditutup berurutan supaya tidak ada periode "bolong" di tengah), tapi JANGAN diklaim bug pasti tanpa baca kode — tulis "belum diverifikasi ke kode" kalau tidak sempat cek |
| Positif — close berurutan                                    | Close Minggu 2 → Minggu 3 → Minggu 4 satu-satu, masing-masing `PUT client-master/accounting-period/close`                                                                             | 200 tiap satu, `is_closed:true` untuk 4 periode pertama                                                                                                                                                                                                                                                                                                                                                          |
| Positif — Lock (kalau endpoint terpisah dari Close tersedia) | `PUT client-master/accounting-period/lock {id:<Minggu 1>}`                                                                                                                            | 200, `is_locked:true` — beda dari `is_closed`, biasanya `lock` MENCEGAH reopen (lapisan kontrol lebih ketat), verifikasi behavior aktual: coba reopen periode yang sudah `is_locked:true`                                                                                                                                                                                                                        |
| Negatif                                                      | Reopen periode yang sudah `is_locked:true`                                                                                                                                            | Ditolak — kalau ternyata BISA reopen periode locked, itu gap kontrol (locked seharusnya kunci permanen sampai di-unlock eksplisit oleh admin), catat sebagai temuan                                                                                                                                                                                                                                              |
| Netralisasi                                                  | Kalau habis test lock/unlock, pastikan Minggu 1-4 balik ke state `is_closed:true` (siap dipakai §3)                                                                                   |

## 3. Close Fiscal Year — Guard "Masih Ada Periode Lain Belum Ditutup"

**Konteks khusus suite ini**: karena periode MINGGUAN (bukan bulanan/kuartalan), 1 tahun fiskal berisi puluhan periode (~52-53, tergantung hasil generator di file 00 §5) — jauh lebih banyak dari 2 suite lain. Suite ini SENGAJA hanya mengisi transaksi di 4 minggu pertama, sehingga percobaan Close Fiscal Year di sini seharusnya DITOLAK karena Minggu 5 dan seterusnya masih `is_closed:false`.

| Skenario                                                              | Detail                                                                                                                | Hasil                                                                                                                                                                                                                                                                                                                          |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Negatif — close tahun fiskal padahal masih banyak periode terbuka** | `PUT client-master/fiscal-year/close {id:<FY2026>}` (setelah hanya Minggu 1-4 yang closed dari total puluhan periode) | Ditolak dengan pesan jelas (mis. "not_all_accounting_periods_are_closed" atau serupa) — ini PERILAKU YANG DIHARAPKAN (bukan gap), justru kalau ternyata BERHASIL close walau periode 5-52 masih terbuka, itu 🆕 bug guard yang serius (tahun fiskal closed tapi transaksi ke periode terbuka sisa tahun jadi ambigu statusnya) |
| Positif — pesan error mencantumkan periode mana yang menghalangi      | Baca detail pesan error                                                                                               | Idealnya menyebut jumlah/periode yang belum closed (mis. "48 periode belum ditutup") — kalau pesannya generik tanpa detail, itu bukan bug fungsional tapi 🔧 improvement UX kecil (user harus buka daftar periode manual untuk tahu mana yang belum closed)                                                                    |

**Catatan scope**: suite ini TIDAK melanjutkan sampai benar-benar berhasil Close Fiscal Year (butuh mengisi ~48 periode mingguan tersisa dengan transaksi/close kosong, di luar scope "transaksi akurasi kecil" yang jadi fokus utama suite ini). Kalau mau menguji Close Fiscal Year sampai SUKSES dengan periode mingguan penuh, itu perluasan terpisah — bisa close sisa periode 5-52 TANPA transaksi (periode kosong, closing entry Rp0) untuk sekadar membuktikan jalur sukses, lalu jalankan skenario di §3.1 di bawah.

### 3.1 (Opsional, lanjutan) Close seluruh periode kosong lalu Close Fiscal Year sukses

| Skenario           | Detail                                                                                                                                                                                                                                                                                                                                                | Hasil                                                                                                                                                                                                                                                                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif — opsional | Close semua periode Minggu 5 s/d periode terakhir tahun 2026 (tanpa transaksi apapun di dalamnya, cukup `PUT .../close` satu-satu atau bulk kalau tersedia) lalu `PUT client-master/fiscal-year/close {id:<FY2026>}`                                                                                                                                  | 200 — closing entry terposting: net Laba/Rugi berjalan (dari §4 file 02, **rugi 12.832.000**) dipindahkan dari akun Pendapatan/Beban ke 3102 Laba Ditahan. Setelah closing, saldo 3102 = **kredit −12.832.000** (atau ditampilkan sebagai debit 12.832.000 tergantung konvensi sign), SEMUA akun Pendapatan (4101-4104) dan Beban (5101-5207) kembali ke 0 |
| Negatif            | Close fiscal year 2x                                                                                                                                                                                                                                                                                                                                  | Ditolak — sudah closed                                                                                                                                                                                                                                                                                                                                     |
| Netralisasi        | Kalau cuma ingin verifikasi jalur ini tanpa mengunci data testing selanjutnya, JANGAN dieksekusi di branch yang sama dipakai file 04/05/06 (karena setelah close year, banyak endpoint mengasumsikan tahun berjalan masih terbuka) — lakukan di branch/clone terpisah kalau tersedia, atau kerjakan file ini PALING TERAKHIR setelah 04/05/06 selesai |
