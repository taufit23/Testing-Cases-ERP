# 06. Rekonsiliasi Bank Dual-Currency & Pajak

> Prasyarat: [`05`](./05-general-ledger-trial-balance-dan-laporan-keuangan.id.md) lengkap. Saldo GL akhir per 2026-03-31: AST-02 BCA Operasional = 23.600.000 (IDR murni), AST-03 BCA Valas = 15.050.000 (IDR, hasil blend beberapa kurs historis — setara USD 1.000 tersisa: 5.000 opening − 3.000 §2.3 − 1.000 §2.5). Endpoint: **Bank Reconciliations**, **Tax Summary**.

## 6.1 Rekonsiliasi BCA Operasional (IDR) — Regresi Standar

| Skenario                                                            | Payload kunci                                                                                                                                                                                              | Hasil                                                                                                                                                                                                 |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif — cocok sempurna                                            | `POST finance/bank-reconciliations/create {bank_account_id:<AST-02>, period_start:"2026-01-01", period_end:"2026-03-31", opening_balance:200000000, closing_balance:23600000, statement_balance:23600000}` | 201, `difference:0`, status bisa langsung `completed`                                                                                                                                                 |
| **Positif — variasi selisih umum (biaya admin bank belum dicatat)** | Statement bank menunjukkan `23400000` (lebih kecil 200.000 — ada biaya admin bulanan yang belum dijurnal)                                                                                                  | `difference: -200000` (atau 200000 tergantung arah), status TETAP `draft` sampai user tambah jurnal biaya admin dan closing_balance disesuaikan — verifikasi tidak auto-`completed` kalau ada selisih |
| Netralisasi                                                         | `delete` reconciliation test, atau `status:draft` jangan `completed` kalau mau diulang                                                                                                                     |

## 6.2 Rekonsiliasi BCA Valas (USD) — Skema Baru, Ada Temuan

**Dikonfirmasi lewat migration `bank_reconciliations`**: kolom `statement_balance`/`opening_balance`/`closing_balance` semuanya `decimal(20,2)` POLOS — tidak ada kolom `currency_id` di tabel ini sama sekali, dan controller (`BankReconciliations.php`) tidak menyentuh currency/exchange rate di titik manapun. Rekonsiliasi ini **sepenuhnya currency-naive**.

| Skenario                                                                           | Detail                                                                                                                                                                                                                                                                                                                                               | Hasil                                                                                                                                                                                                                                                                                                                     | Label temuan                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Negatif (operasional) — coba rekonsiliasi pakai statement asli dari bank (USD)** | BCA mengirim rekening koran BCA Valas dalam format "USD 1,000.00" (mata uang asli rekening) — coba `POST finance/bank-reconciliations/create {bank_account_id:<AST-03>, ..., statement_balance:1000}`                                                                                                                                                | 201 — TAPI `closing_balance` (GL, dalam IDR = 15.050.000) dibandingkan LANGSUNG dengan `statement_balance:1000` (angka USD mentah) → `difference` akan menunjukkan selisih RAKSASA (≈15.049.000) yang SAMA SEKALI BUKAN selisih riil, cuma akibat unit mata uang yang beda (IDR vs USD dibandingkan seolah sama-sama IDR) | 🆕 **Fitur baru (gap nyata)**: rekonsiliasi bank untuk akun ber-`currency_id` asing butuh salah satu dari: (a) field `statement_balance` diinterpretasikan dalam mata uang akun tsb lalu dikonversi otomatis pakai `ExchangeRate::rateFor()` (rate yang SEDANG AKTIF — sistem ini tidak punya rate historis per tanggal, jadi tidak ada konsep "kurs pada `period_end`"), atau (b) UI eksplisit minta user input `statement_balance` SUDAH dalam IDR (user konversi manual sendiri di luar sistem, kurang ideal tapi minimal tidak menyesatkan). Kondisi SEKARANG (opsi c: user harus tahu sendiri untuk convert manual SEBELUM input, tanpa petunjuk apapun dari form) paling rawan salah |
| **Workaround yang benar (sampai fitur di atas ada)**                               | User HARUS mengonversi manual: `statement_balance` = USD 1.000 × rate USD yang SEDANG AKTIF saat ini (`ExchangeRate::rateFor()` mengambil row `is_active=true`, BUKAN rate "pada tanggal `period_end`" — sistem tidak punya konsep rate historis per tanggal). Rate yang aktif di titik ini adalah 15.600 (hasil `activate` terakhir di [`02`](./02-multi-currency-dan-selisih-kurs.id.md) §2.5) → estimasi wajar `statement_balance: 15600000` (1.000×15.600) | `difference` = 15.050.000 − 15.600.000 = **-550.000** — selisih ini REALISTIS (mencerminkan blend kurs historis yang sudah terpakai di GL vs rate yang sedang aktif hari ini), BUKAN bug seperti baris di atas                                                                                                                       | —                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Netralisasi                                                                        | Hapus reconciliation test yang salah (baris pertama), simpan yang benar sebagai baseline kalau mau lanjut                                                                                                                                                                                                                                            |

## 6.3 Rekap PPN Masukan/Keluaran (**Tax Summary**)

| Skenario                             | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Hasil                                                                                                                                                                                                                                                                                        |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif                              | `POST reports/tax-summary {date_from:"2026-01-01", date_to:"2026-03-31"}`                                                                                                                                                                                                                                                                                                                                                                                                                                                        | PPN Masukan (AST-08) = **4.400.000** (dari [`01`](./01-jurnal-manual-arus-biaya-produksi-dan-pinjaman.id.md) §1.1 — pembelian lokal saja), PPN Keluaran (LIA-03) = **7.700.000** (dari §1.6 — penjualan Lini A). PPN Kurang/Lebih Bayar = 7.700.000 − 4.400.000 = **kurang bayar 3.300.000** |
| **Catatan keterbatasan (bukan bug)** | Pembelian impor dari Emerald Bay Trading ([`02`](./02-multi-currency-dan-selisih-kurs.id.md) §2.1/§2.5) TIDAK menghasilkan PPN Masukan sama sekali di suite ini — sesuai catatan scope di [`00`](./00-profil-perusahaan-dan-master-data.id.md) §7 (PPN Impor/Bea Masuk sengaja tidak dimodelkan). Kalau tax-summary di atas SECARA TIDAK SENGAJA sudah menghitung sesuatu dari transaksi impor (padahal tidak ada baris ber-`is_tax` di jurnal §2.1/§2.5), itu bug — laporkan, karena seharusnya memang nol kontribusi dari sana |
| **Catatan**                          | PPh 21 Karyawan (LIA-04, saldo akhir 4.500.000) TIDAK muncul di laporan ini — `reports/tax-summary` scope-nya PPN saja (dikonfirmasi via nama endpoint & suite lama), PPh 21 murni liability biasa tanpa laporan khusus. Bukan gap, di luar scope pajak yang dites suite ini                                                                                                                                                                                                                                                     |
