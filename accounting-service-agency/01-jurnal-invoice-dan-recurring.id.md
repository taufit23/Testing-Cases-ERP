# 01. Jurnal Invoice & Recurring

> **Ciri Khas Skenario**: Fokus pada pengakuan pendapatan bertahap (amortisasi retainer), tagihan recurring, dan pelacakan profitabilitas per divisi (Marketing vs Dev).
> Format pengujian mengikuti standar: **Positif** (jalur normal harus sukses) / **Negatif** (input salah harus ditolak) / **Netralisasi** (rollback).
> Semua endpoint di **Journals**. Prasyarat: master data di [`00-profil-perusahaan-dan-master-data.id.md`](./00-profil-perusahaan-dan-master-data.id.md) sudah ada.

> ⚠️ **Catatan penting — "recurring billing" TIDAK ada sebagai fitur otomatis di backend.** Tidak ditemukan model/controller/kolom apa pun untuk recurring invoice (`grep -ri recurring` di `app/` nihil kecuali dokumen test ini). Judul file mengacu ke transaksi retainer bulanan yang **dicatat manual berulang tiap bulan lewat Journals — `create`** — bukan job terjadwal atau fitur "buat invoice otomatis". Jangan uji fitur otomasi yang tidak ada.

## 1.1 Create Jurnal — Invoice Retainer Bulanan (Divisi Marketing)

Transaksi: tagih retainer bulanan client Divisi Digital Marketing Rp 10.000.000 + PPN Keluaran 11% (Rp 1.100.000).

| Skenario                | Payload kunci                                                                                                                                                                                                                                                                                                          | Hasil                                                                                                                                                                                                                                                                                      |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Positif                 | `POST accounting/journals/create {code:"JRN-XXX", date:"2026-08-05", lines:[{account_id:<Piutang Usaha AST-03>, debit:11100000}, {account_id:<Pendapatan Jasa Digital Marketing PDT-01>, credit:10000000, business_unit_id:<DIV-MKT>, tax_rate:11}, {account_id:<PPN Keluaran LIA-02>, credit:1100000, tax_rate:11}]}` | **200** (bukan 201 — macro `successWithData` selalu `response()->json($response, 200)`), journal dibuat dengan status **draft/pending-review**, `posted_at` MASIH NULL. Journal **belum ter-GL** sampai `PUT accounting/journals/post` dipanggil terpisah — create TIDAK otomatis posting. |
| Negatif — tidak balance | Salah ketik credit PPN jadi 1.000.000 (bukan 1.100.000)                                                                                                                                                                                                                                                                | Journal tetap tersimpan tapi jatuh ke status **draft** (bukan pending-review), tidak masuk approval — cek via `show`, JANGAN asumsikan ditolak dengan error                                                                                                                                |
| Negatif — lines < 2     | Kirim 1 baris saja                                                                                                                                                                                                                                                                                                     | 422, `lines` minimal 2 (`min:2`)                                                                                                                                                                                                                                                           |
| Negatif — akun fiktif   | `account_id` tidak ada di COA                                                                                                                                                                                                                                                                                          | 422                                                                                                                                                                                                                                                                                        |
| Lanjutan                | `PUT accounting/journals/post {id}`                                                                                                                                                                                                                                                                                    | `posted_at` terisi, `general_ledgers` baru dibuat — verifikasi lewat file 02                                                                                                                                                                                                               |
| Netralisasi             | `DELETE accounting/journals/delete {id}` (selama draft/belum posted), atau `POST accounting/journals/reverse` kalau sudah posted                                                                                                                                                                                       |

## 1.2 Create Jurnal — Pengakuan Pendapatan Diterima Dimuka (Divisi Dev)

Transaksi: klien Divisi Software Development sudah bayar di muka (tercatat di saldo awal LIA-03 Rp 20.000.000). Bulan ini diakui sebagian Rp 5.000.000 sebagai pendapatan karena progres proyek berjalan.

| Skenario                                                       | Payload kunci                                                                                                                                                                                                 | Hasil                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif                                                        | `lines:[{account_id:<Pendapatan Diterima Dimuka LIA-03>, debit:5000000, business_unit_id:<DIV-DEV>}, {account_id:<Pendapatan Jasa Software Development PDT-02>, credit:5000000, business_unit_id:<DIV-DEV>}]` | 200, journal draft/pending-review, balance Dr=Cr=5.000.000                                                                                                                                                                                                                                                                    |
| Negatif — amortisasi melebihi saldo Pendapatan Diterima Dimuka | Debit LIA-03 sebesar 25.000.000 (saldo cuma 20.000.000)                                                                                                                                                       | **Backend TIDAK memvalidasi saldo akun sebelum posting** — controller `Journal::create()`/`post()` tidak mengecek `chart_of_accounts_balances` sama sekali, hanya cek Dr=Cr di level jurnal. Jurnal akan **lolos dan posted**, akun LIA-03 jadi saldo debit (minus) — dokumentasikan ini sebagai gap, bukan sebagai "ditolak" |
| Netralisasi                                                    | Reverse setelah posted                                                                                                                                                                                        |

## 1.3 Create Jurnal — Bayar Beban Cloud Server Bulanan (Divisi Dev)

Transaksi: bayar tagihan AWS/GCP Rp 2.000.000 dari Bank Mandiri Operasional.

| Skenario    | Payload kunci                                                                                                                                                      | Hasil                                                                                                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif     | `lines:[{account_id:<Beban Sewa Cloud Server BBN-02>, debit:2000000, business_unit_id:<DIV-DEV>}, {account_id:<Bank Mandiri Operasional AST-02>, credit:2000000}]` | 200, setelah `post` saldo Bank Mandiri (via GL, bukan kolom `bank_accounts.balance` langsung — cek `general-ledger/detail-ledger` untuk akun ini) berkurang 2.000.000 |
| Netralisasi | Reverse setelah posted                                                                                                                                             |

## Netralisasi

- Hapus jurnal draft via `DELETE accounting/journals/delete`, atau `POST accounting/journals/reverse` untuk jurnal yang sudah posted (tidak ada "un-post").
