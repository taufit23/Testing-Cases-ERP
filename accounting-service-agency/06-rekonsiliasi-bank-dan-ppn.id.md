# 06. Rekonsiliasi Bank & PPN

> **Ciri Khas Skenario**: Fokus pada pengakuan pendapatan bertahap (amortisasi retainer), tagihan recurring, dan pelacakan profitabilitas per divisi (Marketing vs Dev).
> Format pengujian mengikuti standar: **Positif** (jalur normal harus sukses) / **Negatif** (input salah harus ditolak) / **Netralisasi** (rollback).
> Endpoint rekonsiliasi: **Bank Reconciliations**. Endpoint PPN: **Tax Summary**.

> ⚠️ **Model rekonsiliasi bank di backend jauh lebih sederhana dari asumsi awal file ini**: `BankReconciliation` cuma header (`opening_balance`, `closing_balance`, `statement_balance`, `difference = statement_balance - closing_balance`, `status: draft|completed`). TIDAK ADA line-item matching mutasi per transaksi, TIDAK ADA status "matched", dan TIDAK ADA pembuatan jurnal penyesuaian otomatis (tidak ada logic apa pun di `BankReconciliations::create()/update()/complete()` yang memanggil `Journal`/`JournalHeader`). Semua klaim di bawah sudah disesuaikan dengan behavior aktual.

## 1. Buat Rekonsiliasi (`POST finance/bank-reconciliations/create`)

| Skenario              | Payload kunci                                                                                                                                                                                                            | Hasil                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif               | `{bank_account_id:<Bank Mandiri Operasional>, period_start:"2026-08-01", period_end:"2026-08-31", opening_balance:150000000, closing_balance:<saldo GL akhir Agustus>, statement_balance:<saldo mutasi rekening koran>}` | 200, `reconciliation_number` auto-generate format `RCN/YYYY/MM/0001`, `status:"draft"`, `difference` dihitung otomatis (`statement_balance - closing_balance`) |
| Positif — selisih nol | `statement_balance` sama persis dengan `closing_balance`                                                                                                                                                                 | `difference: 0`                                                                                                                                                |

## 2. Selisih Saldo (biaya admin bank, dsb)

| Skenario                                                       | Detail                                                                                                              | Hasil                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ❌ **Tidak ada fitur "item penyesuaian" atau jurnal otomatis** | Backend tidak punya endpoint/kolom untuk menambah baris penyesuaian (biaya admin/pajak bunga) di dalam rekonsiliasi | Kalau ada selisih karena biaya admin bank yang belum dicatat, harus dibuat **jurnal manual terpisah** dulu via `accounting/journals/create` (Dr Beban Administrasi Bank / Cr Bank Mandiri Operasional) supaya `closing_balance` versi sistem berubah, BARU update rekonsiliasi (`PUT finance/bank-reconciliations/update`) dengan `closing_balance` baru sampai `difference` mendekati/sama 0 |

## 3. Complete Rekonsiliasi (`POST finance/bank-reconciliations/complete`)

| Skenario                                                            | Detail                                                 | Hasil                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif                                                             | `difference = 0` → `complete {slug}`                   | 200, `status:"completed"`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 🐞 **Negatif — selisih tidak nol memicu bug 500, BUKAN 422 bersih** | `difference != 0` → `complete {slug}`                  | Controller memanggil `response()->warn([...])` di `BankReconciliations::complete()` — **macro `warn()` TIDAK terdaftar** di `MacroServiceProvider` (hanya ada `successWithData`, `validatorFail`, `authSuccess`, `successWithData1`, `error`). Ini akan melempar `BadMethodCallException` yang berujung **HTTP 500** (generic error handler), bukan pesan validasi rapi "422 Unbalanced reconciliation" seperti asumsi semula. Laporkan sebagai bug ke tim dev — perbaikannya ganti `->warn(...)` jadi `->error(...)` atau macro baru |
| Negatif — bukan draft                                               | Complete rekonsiliasi yang statusnya sudah `completed` | `firstOrFail()` pada query `where('status','draft')` gagal menemukan record → exception (kemungkinan besar 404/500 tergantung handler, bukan 422 khusus)                                                                                                                                                                                                                                                                                                                                                                              |

## 4. Rekap PPN (`POST reports/tax-summary`)

| Skenario | Payload kunci                                                       | Hasil                                                                                                                                                                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif  | `{start_date:"2026-08-01", end_date:"2026-08-31"}`                  | 200, rekap dibaca dari tabel `journal_taxes` — HANYA baris jurnal yang akunnya ber-flag `is_tax:true` DAN dikirim `tax_rate` saat create yang muncul di sini. Pastikan semua jurnal PPN Keluaran (file 01 §1.1) dan PPN Masukan (kalau ada pembelian jasa dengan PPN Masukan) sudah posted sebelum generate laporan ini |
| Negatif  | Jurnal PPN yang dibuat TANPA `tax_rate` di baris akun `is_tax:true` | Baris tersebut TIDAK akan muncul di `journal_taxes` sama sekali — bukan error, tapi silent-missing dari rekap. Selalu sertakan `tax_rate` saat baris melibatkan akun `is_tax:true`                                                                                                                                      |

## Netralisasi

- `DELETE finance/bank-reconciliations/delete` hanya berlaku untuk status `draft`.
- Reverse jurnal penyesuaian manual yang sudah posted via `accounting/journals/reverse`.
