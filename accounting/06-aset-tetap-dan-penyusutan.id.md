# 06. Aset Tetap & Penyusutan

> Prasyarat: akun 1201 (Peralatan Toko) & 1202 (Akumulasi Penyusutan Peralatan Toko) dari §00 sudah ada. Diakses lewat halaman **Fixed Assets → Assets** di FE (`fixed-assets/assets`), endpoint backend ada di namespace `Finance`, bukan `Accounting`.
>
> **BARU (2026-08-10) — konteks tahun buku berubah:** FY2026 sudah ditutup (lihat [`03-tutup-periode-dan-tahun-fiskal.id.md`](./03-tutup-periode-dan-tahun-fiskal.id.md) §3.3), fiscal year aktif sekarang FY2027. Semua tanggal di file ini digeser ke 2027 — BUKAN cuma kosmetik: kalau tetap pakai tanggal 2026, `Run Depreciation` akan DITOLAK backend (`no_active_accounting_period`) karena semua Accounting Period 2026 sekarang closed/locked, sama seperti guard yang sudah dibuktikan di file 03 untuk posting jurnal manual biasa.

## Konsep Dasar Tambahan (Khusus File Ini)

| Istilah                       | Keterangan                                                                                                                                                                                                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Aset Tetap**                | Barang yang dibeli perusahaan untuk DIPAKAI bertahun-tahun (rak, mesin kasir, motor), BUKAN untuk dijual lagi (beda dari Persediaan). Karena manfaatnya bertahun-tahun, biayanya juga "disebar" bertahun-tahun lewat penyusutan — bukan langsung jadi beban penuh di bulan beli.    |
| **Penyusutan (Depreciation)** | Proses mengakui SEBAGIAN nilai aset sebagai beban tiap bulan, sampai nilainya habis (atau tersisa nilai residu). Kenapa tidak dibebankan sekaligus di bulan beli? Karena kalau aset itu masih dipakai 5 tahun, mencatat semua biayanya di bulan pertama akan bikin laba bulan itu kelihatan jelek padahal manfaatnya masih dinikmati 5 tahun ke depan.                                              |
| **Nilai Residu (`salvage_value`)** | Perkiraan nilai jual aset itu di AKHIR masa pakainya (kalau nol, berarti diperkirakan sudah tidak ada nilai jual sama sekali). Yang disusutkan cuma selisih Harga Perolehan − Nilai Residu, bukan seluruh harga beli.                                                              |
| **Masa Manfaat (`useful_life_months`)** | Perkiraan berapa lama aset itu akan dipakai (dalam bulan) — menentukan seberapa cepat nilainya disusutkan.                                                                                                                                                                       |
| **Garis Lurus vs Saldo Menurun** | **Garis Lurus (straight-line)**: nominal penyusutan SAMA setiap bulan (harga dibagi rata ke semua bulan masa manfaat). **Saldo Menurun (declining balance)**: nominal penyusutan lebih BESAR di awal, makin lama makin KECIL (dihitung dari sisa nilai buku yang terus menurun, bukan harga asli) — cocok untuk aset yang manfaatnya cepat berkurang di awal (mis. kendaraan).                        |
| **Book Value (Nilai Buku)**   | Harga Perolehan dikurangi TOTAL penyusutan yang sudah berjalan sampai sekarang — ini angka yang terus turun tiap bulan seiring aset "dipakai".                                                                                                                                   |
| **Akumulasi Penyusutan**      | Akun kontra-aset (lihat glosarium file 00) yang menampung TOTAL penyusutan dari waktu ke waktu — bukan beban bulan ini saja, tapi akumulasi semua bulan sejak aset mulai disusutkan.                                                                                             |
| **Disposal (Pelepasan Aset)** | Aset dijual/dibuang/rusak permanen sebelum atau sesudah masa manfaatnya habis — mengakhiri "riwayat hidup" aset itu di sistem, `current_book_value` dinolkan/difinalkan.                                                                                                          |

## 6.1 Registrasi Aset — 3 Variasi

| #   | Nama Aset                  | Kategori (enum `category`)   | Harga Perolehan | Nilai Residu | Masa Manfaat       | Metode Penyusutan                 |
| --- | -------------------------- | ---------------------------- | --------------- | ------------ | ------------------ | --------------------------------- |
| 1   | Rak Display Toko Pusat     | `equipment` (Peralatan Toko) | Rp 36.000.000   | Rp 0         | 60 bulan (5 tahun) | Garis Lurus (straight-line)       |
| 2   | Mesin Kasir POS Toko Pusat | `equipment` (Peralatan Toko) | Rp 15.000.000   | Rp 1.500.000 | 36 bulan (3 tahun) | Garis Lurus                       |
| 3   | Motor Box Pengantar Barang | `vehicle` (Kendaraan)        | Rp 24.000.000   | Rp 4.000.000 | 48 bulan (4 tahun) | Saldo Menurun (declining balance) |

> **Kontrak field asli Assets — `create`** (verifikasi baca kode langsung, `App\Http\Controllers\Finance\FixedAssets::create()`):
> - `asset_code` TIDAK bisa diisi manual — server SELALU generate sendiri format `FA/{tahun}/{urutan}` (mis. `FA/2027/0001`), field ini bahkan tidak ada input-nya di form Create Asset.
> - `category` di form Create Asset berupa **dropdown 6 pilihan tetap** (Land/Building/Vehicle/Equipment/Furniture/Intangible), BUKAN teks bebas — jadi kesalahan input teks bebas seperti "Peralatan Toko"/"Kendaraan" TIDAK mungkin terjadi lewat UI (lihat pemetaan di kolom Kategori di atas untuk milih dropdown yang benar).
> - Field nilai residu di form berlabel **Salvage Value** (bukan "Residual Value").
> - `current_book_value` saat registrasi = **full Acquisition Cost** (BUKAN dikurangi Salvage Value di muka) — book value baru turun setelah penyusutan beneran di-run (§6.2).
> - Form Create Asset juga punya card **Chart of Accounts** dengan 3 dropdown opsional: **Asset Account**, **Depreciation Expense Account**, **Accumulated Depreciation Account** — kalau dikosongkan, aset tetap tersimpan tapi toast warning "Depreciation account not configured" muncul setelah save (penyusutan nanti TIDAK akan posting ke GL sampai akun-akun ini diisi lewat tombol **Edit Chart of Accounts** di halaman detail — lihat catatan baru di §6.2).
>
> **Pemetaan akun COA yang WAJIB dipakai untuk ketiga aset di §6.1** (ketiganya berbagi akun yang sama walau beda kategori barang — tetap "Peralatan Toko" secara akuntansi):
> - **Asset Account** = 1201 (Peralatan Toko)
> - **Depreciation Expense Account** = 5204 (Beban Penyusutan Peralatan Toko)
> - **Accumulated Depreciation Account** = 1202 (Akumulasi Penyusutan Peralatan Toko)

| Negatif      | Field **Depreciation Method** hanya berupa dropdown dari opsi yang didukung backend — coba kirim value di luar enum tidak mungkin lewat UI normal, tapi kalau dropdown kosong/tidak dipilih → klik **Save**                                                                                                                                                    | Form menolak submit / backend menolak dengan pesan validasi                                                                                                           |

## 6.2 Jalankan Penyusutan Bulanan

Skenario: akhir Januari 2027, akuntan menjalankan proses penyusutan bulanan untuk semua aset aktif.

> **Menghubungkan COA setelah aset dibuat (kalau §6.1 sengaja/tidak sengaja dikosongkan):** halaman detail aset (`fixed-assets/assets/{slug}`) punya tombol **Edit Chart of Accounts** di navbar (dan ikon pensil kecil di header card **Chart of Accounts**) — klik untuk buka modal berisi 3 dropdown yang sama seperti di form Create (**Asset Account**, **Depreciation Expense Account**, **Accumulated Depreciation Account**), isi dengan pemetaan akun 1201/5204/1202 yang sama seperti di §6.1, lalu **Save**. Endpoint di baliknya `PUT fixed-assets/assets/update` (`App\Http\Controllers\Finance\FixedAssets::update()`) — field yang sama persis dengan yang diterima saat create, tidak ada endpoint terpisah. **Run Depreciation WAJIB dijalankan SETELAH COA terisi** — kalau dijalankan sebelum COA lengkap, baris tetap masuk ke Depreciation Schedule tapi TIDAK ada jurnal GL yang ter-post (lihat baris "posting GL otomatis" di bawah).

| Skenario                                       | Langkah di UI                                                                                                                                                                                                            | Hasil                                                                                                                                                                                                                            |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positif                                        | Untuk tiap aset: buka halaman detail aset (`fixed-assets/assets/{slug}`) → klik tombol **Run Depreciation** di navbar → modal terbuka, isi field **Period Date** = `2027-01-01` → klik **Run Depreciation** untuk konfirmasi                                                     | Toast sukses "Depreciation run success", tabel **Depreciation Schedule** di halaman detail bertambah 1 baris baru, `Book Value` (kartu metrik atas) berkurang sesuai nominal penyusutan bulan itu                                                                                                          |
| **Positif — hubungkan COA lewat Edit (bukan saat create)** | Buat 1 aset test tambahan lewat Create Asset TANPA isi card Chart of Accounts sama sekali (biarkan ketiga dropdown kosong) → Save → toast warning "Depreciation account not configured" muncul → buka halaman detail aset itu → klik **Edit Chart of Accounts** → isi Asset Account = 1201, Depreciation Expense Account = 5204, Accumulated Depreciation Account = 1202 → **Save** | Toast sukses update, card **Chart of Accounts** di halaman detail langsung menampilkan ketiga akun (bukan lagi pesan "belum dikonfigurasi") — lanjutkan Run Depreciation untuk aset ini dan pastikan jurnal GL ikut ter-post sama seperti 3 aset lain |
| **Positif — verifikasi nominal garis lurus**   | Aset #1 (Rak Display): `(36.000.000 − 0) / 60 = Rp 600.000/bulan`, cek baris Januari di tabel Depreciation Schedule                                                                                                                                 | Nominal penyusutan Januari yang tampil di tabel = Rp 600.000 tepat                                                                                                                                                                                    |
| **Positif — verifikasi nominal saldo menurun** | Aset #3 (Motor Box): jalankan Run Depreciation untuk Januari lalu Februari 2027 (2× berturut-turut dengan Period Date berbeda), lalu bandingkan 2 baris teratas di tabel Depreciation Schedule                                                                    | Nominal Februari harus LEBIH KECIL dari Januari (ciri khas saldo menurun, beda dengan garis lurus yang nominalnya selalu sama tiap bulan)                               |
| **Positif — posting GL otomatis**              | Setelah Run Depreciation, buka [`02-general-ledger-neraca-saldo.id.md`](./02-general-ledger-neraca-saldo.id.md) atau Trial Balance dan cari jurnal penyusutan bulan itu                                                                                                                                           | Harus ADA jurnal baru `Dr Beban Penyusutan Peralatan Toko / Cr Akumulasi Penyusutan Peralatan Toko` — bukan cuma baris di Depreciation Schedule tanpa jurnal (fix yang sudah dilakukan Phase 4 — sebelumnya baris penyusutan dibuat tapi tidak pernah ter-link ke jurnal) |
| **Negatif — double posting**                   | Di halaman detail aset yang sama, klik **Run Depreciation** lagi dengan **Period Date** bulan Januari 2027 yang SAMA (bulan yang sudah pernah diproses)                                                                                                           | Ditolak atau di-skip oleh backend (toast error, atau tidak ada baris baru bertambah) — sistem harus mencegah penyusutan ganda untuk bulan yang sama per aset, tabel Depreciation Schedule TIDAK boleh punya baris kedua untuk Januari                                                                     |
| Positif — bulan berikutnya                     | Klik **Run Depreciation** lagi dengan **Period Date** = `2027-02-01`                                                                                                                                                                                      | Baris baru terbuat di tabel Depreciation Schedule, `Book Value` berkurang lagi (kumulatif)                                                                                                                                                              |
| Netralisasi                                    | Tidak ada tombol "un-depreciate" di UI — kalau salah proses, koreksi lewat jurnal manual balik (Dr Akumulasi Penyusutan / Cr Beban Penyusutan) di halaman Jurnal Manual mengikuti pola reverse manual, BUKAN hapus baris di Depreciation Schedule |

**Sebab-akibat:** baris "posting GL otomatis" penting karena dulu (sebelum diperbaiki) penyusutan TERCATAT di tabel `asset_depreciations` tapi TIDAK PERNAH benar-benar mengubah saldo akun di General Ledger — akibatnya `current_book_value` di halaman Aset kelihatan turun, tapi Neraca (Balance Sheet, file 04) tidak ikut berubah sama sekali karena datanya beda sumber. Ini kenapa §6.3 di bawah wajib silang-cek ke Trial Balance, bukan cuma percaya angka di halaman Aset saja. Baris "double posting" juga penting: kalau proses ini bisa dijalankan berkali-kali untuk bulan yang sama, beban penyusutan akan tercatat DOBEL (atau lebih) di GL padahal aset fisiknya cuma "termakan waktu" sekali — bikin Beban Penyusutan di Laba Rugi jadi terlalu besar tanpa alasan.
